# Client state: who owns what (9 Nov 2026; classes added 12 Nov, the chat's usage and budget 21 Nov)

Read this before changing the workspace screen, the editor's sync, the chat or the live preview.
Most bugs found on 9 Nov came from state with more than one owner, or a rule that lived in one
place and was assumed in another. Paths are under `packages/client/src`.

## Rules that cross files

1. **Flush before a turn.** Accept, Reject and typing travel as logged events in batches, and
   the editor's commands queue. A chat message or an @model comment answer first runs the screen's
   `beforeTurn` (flush, then take the typing mark), waiting at most 5 s (`FLUSH_LIMIT_MS`):
   `logger.flush()` never resolves while the server refuses a batch.
2. **A reply wins over typing the server already had.** `useTurnReply` merges with
   `keepNewerTyping(changes, typingMark)`; -1 (keep all typing) only when there is no mark.
   Editing mode, typing during the turn: the server merges it into the assistant's change
   (`server/src/gateway/typed-during.ts`, `shared/src/textMerge.ts`) and lists the block in
   `typed_during`; the screen then takes the server's text for it. Suggesting mode, a blank doc:
   the turn goes straight in (`shared/src/canvas/newDocs.ts`), unless typing reached the server
   before the commit, when its changes come as suggestions like any other. When the doc locks for the
   preview, the editor's batch is flushed first (`editor/Canvas.tsx`), so the commit sees the
   last keystrokes.
3. **The preview is display only, and a copy.** `previewReply` copies blocks and docs; nothing
   in it reaches the snapshot until the server's reply does.
4. **The pane and the screen render a turn's end together.** `ChatPane` mirrors its store into
   ordinary React state; `useSyncExternalStore` rendered the pane ahead of the screen, so the
   turn's end and the new snapshot landed a render apart and the editor took a suggestion in as
   plain text. Unit tests (jsdom) cannot see this: repeat the e2e test instead (below).
5. **A turn outlives its pane.** Switching chat mid-turn leaves the turn running on the server;
   the pane takes its draft back, and its reply is still merged (a new doc opens only if the
   teacher is still in that chat).

6. **A class is fetched in one place.** `state/classDetail.ts` holds the only copy of a class's
   pupils, adaptations and curriculum. A component that shows them calls `useClassDetail`; one
   that changes them saves to the server first, then calls `update`. It uses
   `useSyncExternalStore`, which rule 4 warns about for the chat: here nothing has to land in
   the same render as the snapshot, so it is safe, but do not hang editor state off it.
7. **Components should not import from `screens/`.** Shared pure logic lives in `state/`
   (`assistantMode.ts`, `classList.ts`, `classDetail.ts`). Two imports are left to move:
   `components/mentions/CurriculumMention.tsx` (`screens/classes/curriculumView`) and
   `components/FontNotice.tsx` (`screens/useFontNotice`).

8. **Save before leaving /w.** "Sign out" (the account menu, `/w` only) first runs the save
   that `screens/useDocActions.ts` registers through `useSaveBeforeSignOut`
   (`components/sidebar/accountContext.ts`): the editor's flush if one is open, then
   `logger.flush()`. It waits at most 5 s (`SIGN_OUT_SAVE_LIMIT_MS`, `state/account.ts`), for
   the reason in rule 1, then `POST /api/auth/sign-out`. The workspace is made `inert`
   (mouse and keyboard) before the save's first step, and covered with a message, so nothing
   is typed after the save began. If the server cannot be told, the person
   stays signed in and the menu says so. `e2e/accounts.spec.ts` types and signs out at once.
   "Dashboard" (admins only, the sidebar's last row above the account chip) does the same save,
   inert and cover (`saveBeforeLeaving`, `state/account.ts`), then leaves for `/admin` by a full
   page load, with no sign-out call; a Ctrl or middle click opens a new tab without saving, as
   any link. `e2e/dashboard.spec.ts` types, holds the editor's requests and clicks Dashboard at
   once, so it fails if the page does not wait. Back to a page left this way can bring it out of
   the browser's back-forward cache still covered and inert: `AccountApp` reloads on a
   `pageshow` with `persisted`, but only when the page was left on purpose (Dashboard, Sign
   out). A page left any other way comes back as it was: its editor batch and the logger's
   queue may still hold typing, and a reload would lose it. Both cases are in the same spec,
   in Playwright's full Chromium with the cache on (its default headless shell has no cache).
   Without the cache, the editor's last unsent batch is lost when the page is left by address:
   nothing sends it on `pagehide`. That was so before #79.

## Checking timing changes

A race between the pane, the screen and the editor shows up only in a browser, and only some of
the time. After touching any of the above, repeat the core flow:

```bash
pnpm build && pnpm e2e e2e/core.spec.ts -g "ask, accept" --repeat-each 20 --trace off
```

On 9 Nov all 16 e2e tests passed, and "ask, accept" 30 of 30 (it had failed 3 in 30 on `main`).
